### 000 Core Rules

#### Simplicity & Clarity

- **KISS (Keep It Simple, Stupid)**: Favor simple, straightforward solutions over clever ones
- **Single Level of Abstraction**: Keep function bodies at the same level of abstraction for readability
- **DRY (Don't Repeat Yourself)**: Extract common patterns into reusable functions/modules
- **Explicit over Implicit**: Make intentions clear through naming and structure

#### Documentation Standards

- **Limit Documentation**: Write self-documenting code; only add comments for "why", not "what"
- **No Redundant Docs**: Avoid repeating what the code already says clearly
- **Focus on Intent**: Document business logic, edge cases, and non-obvious decisions
- **Keep It Current**: Update or remove outdated documentation immediately

#### Version Control

- **Atomic Commits**: Every logical change gets a commit with a clear, descriptive message
- **Commit Message Format**: Use conventional commits (feat:, fix:, refactor:, docs:, etc.)
- **Learn from History**: Review git history before making changes to avoid repeating past mistakes

#### Architecture & Design

- **Follow SPEC.md**: Always reference SPEC.md for overall architecture and design decisions
- **Consistency**: Follow established patterns in the codebase
- **Temporal Best Practices**: Follow Temporal workflow and activity patterns
